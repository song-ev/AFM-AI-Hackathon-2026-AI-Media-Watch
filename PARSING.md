# Парсинг и непрерывный поток видео (Stage 1, сбор)

Документ описывает **лучшее решение** для сбора видео из TikTok / YouTube /
Instagram и три режима пакетной обработки, реализованные в коде
(`ingestion/services/bulk.py`).

## Три режима (реализованы)

| Режим | Эндпоинт / команда | Когда использовать |
| ----- | ------------------ | ------------------ |
| Массовые ссылки | `POST /api/ingestion/bulk/` `{text\|urls}` | Есть готовый список 50–200 ссылок |
| Парсинг источника | `POST /api/ingestion/parse/` `{source_url, limit}` | Канал/аккаунт/хэштег — собрать последние N |
| Офлайн-папка | `POST /api/ingestion/folder/` или `python manage.py ingest_folder <dir>` | 50–100 локальных файлов, без сети |

Прогресс пакета: `GET /api/ingestion/batches/` и `/batches/<id>/` (UI:
вкладка **«Поток / пакет»** на странице «Анализ»).

## Лучшее решение по платформам

Архитектурный принцип: **один слой сбора = yt-dlp** (он же используется для
скачивания). Он умеет и перечислять (индекс плейлиста/канала через
`extract_flat`, без скачивания медиа), и скачивать сам файл. Это убирает
зависимость от хрупких самописных HTML-парсеров там, где это возможно.

### YouTube — ✅ работает «из коробки»
- Канал: `https://www.youtube.com/@channel` или `/channel/UC...` → `extract_flat`
  отдаёт список `watch?v=...`.
- Хэштег/поиск: `ytsearchN:запрос`.
- Cookies нужны только для возрастных/региональных ограничений.

### TikTok — ⚠️ работает с cookies + (для масштаба) прокси
- `https://www.tiktok.com/@username` перечисляется yt-dlp; отдельные видео
  скачиваются. Для стабильности нужен **cookies-файл** залогиненной сессии
  (`YTDLP_COOKIES_FILE` в `.env`).
- При большом объёме TikTok банит IP → нужны **резидентские/мобильные прокси с
  ротацией**. yt-dlp: `--proxy` / опция `proxy`.
- Хэштег-страница (`/tag/<word>`) отдаёт меньше и нестабильно — лучше идти по
  конкретным аккаунтам.
- Тяжёлая альтернатива (если yt-dlp перестаёт справляться): headless-браузер
  **Playwright + playwright-stealth** со скроллингом ленты и перехватом
  внутренних JSON-ответов TikTok. Дороже по ресурсам, но устойчивее к защите.
  Это запасной путь, не основной.

### Instagram — ⚠️ обязательны cookies
- Reels/посты аккаунта перечисляются и скачиваются yt-dlp **только с cookies**
  залогиненного аккаунта (`YTDLP_COOKIES_FILE`). Без них — почти всё закрыто.
- Жёсткие лимиты по частоте: обязательно прокси + паузы между запросами.

## Что нужно от вас, чтобы парсинг заработал на полную

1. **Cookies-файл** (Netscape `cookies.txt`) для TikTok и Instagram — экспорт из
   браузера расширением (напр. «Get cookies.txt»), положить на сервер и указать
   путь в `.env`:
   ```
   YTDLP_COOKIES_FILE=/secure/path/cookies.txt
   ```
2. **Прокси** для объёма (резидентские/мобильные с ротацией: Bright Data, Froxy,
   и т.п.). Скажите — добавлю `YTDLP_PROXY` в настройки и проброшу в yt-dlp.
3. (Опционально) сервис решения капч (2Captcha/Anti-Captcha) — нужен только если
   пойдём по пути Playwright для TikTok при срабатывании капчи.

Без cookies/прокси работает: **YouTube** полностью и **офлайн-папка** (любой
объём локальных файлов) — этого достаточно для демо и офлайн-сценария.
